# GitHub ownership routing inventory

Initial inventory: reviewed head `d9d9bc7`. Anchors are regenerated from the merged source with `node scripts/identity-inventory.ts --write` and checked by the same command with `--check`.

Ownership conflicts refuse only selected IDs, board candidates or import targets. The complete peer index still detects any peer claiming an in-scope issue. Conflicts wholly outside scope produce warnings naming both items.

Every operational item-to-issue/PR mapping goes through `githubOwnershipClaims` and the shared consistency/uniqueness checks. A provenance-bearing item is writable only when all its claims agree on one issue and no peer claims that issue. Tags never establish ownership or conflicts; the deprecated upstream flag does not change that.

Inbound import, refresh, atomic replay/finalization, lifecycle metadata, annotations and dependency-source mutations retain the native locked write guard. Dependency endpoints are also revalidated there. Outbound sync/export re-read complete current metadata immediately before each HTTP write; package-built export plans retain their ownership context for direct execution. There is no outbound issue-comment writer: imported comments and blocker annotations write local SDK comments. Projects board/node identities, explicit source arguments and free-form blocker references are separate namespaces, not implied item ownership.

Ownership work is indexed once per complete snapshot. The tracker ownership namespace is leased before SDK workspace/item locks and held through persistence; nested writes reuse the lease. Native batches read peers once before the journal and once for each separately locked SDK write, including comments and metadata finalizers. Nested operations reuse the live lease, never a previous write’s peer snapshot. Outbound writes read one fresh corpus and check only the current target; N writes over M items use at most O(N*M) claim work. The N=40 native and outbound tests count actual reads/parses without replacing SDK storage or using timing assertions.

Scope: all authored root TypeScript modules. The inventory includes identity/ownership helper call sites, raw collectors/parsers, direct reads of `github_url`, `github_repo`, `github_number` and `external_ref`, and raw `gh:` reference regexes. Alias reads through `Object.entries` are covered by the raw-collector rows. Schema/type declarations, field emitters and tag merges serialize data rather than choose a target; `buildImportFidelity`, import mutation builders and project provenance emitters are in that category. Owner claims come from whole-value explicit identity fields, external_ref, or a proven importer ID. A leading native GitHub issue or GH issue/PR declaration retains legacy ownership without a link-only marker or whole-description match; direct provenance still protects against copied provider markers. Generic link fields and their prose produce references only. Operational selectors consume the shared ownership index; provider backlinks and explicit opt-in citation adoption keep their separate first-link authorization.
