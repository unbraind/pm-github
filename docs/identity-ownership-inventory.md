# GitHub ownership routing inventory

Initial inventory: reviewed head `d9d9bc7`, before round-10 production edits. This ledger was refreshed against the completed source so its repository-relative line anchors describe the fix.

Every operational item-to-issue/PR mapping goes through `githubOwnershipClaims` and the shared consistency/uniqueness checks. A provenance-bearing item is writable only when all its claims agree on one issue and no peer claims that issue. Reference-only tags are not owners. The explicit upstream `--allow-reference-tags` opt-in is evaluated inside the same function, including contradiction and peer checks.

Inbound import, refresh, atomic replay/finalization, lifecycle metadata, annotations and dependency-source mutations retain the native locked write guard. Dependency endpoints are also revalidated there. Outbound sync/export re-read complete current metadata immediately before each HTTP write; package-built export plans retain their ownership context for direct execution. There is no outbound issue-comment writer: imported comments and blocker annotations write local SDK comments. Projects board/node identities, explicit source arguments and free-form blocker references are separate namespaces, not implied item ownership.

Scope: all authored root TypeScript modules. The inventory includes identity/ownership helper call sites, raw collectors/parsers, direct reads of `github_url`, `github_repo`, `github_number` and `external_ref`, and raw `gh:` reference regexes. Alias reads through `Object.entries` are covered by the raw-collector rows. Schema/type declarations, field emitters and tag merges serialize data rather than choose a target; `buildImportFidelity`, import mutation builders and project provenance emitters are in that category. Only the raw-collector implementation may interpret provenance fields independently; operational selectors never consume those collectors directly.
